# ovoo

Web UI for the Nomad cluster: jobs, allocations, nodes, storage and ACLs,
with task logs and a terminal. Each user signs in with their own Nomad ACL
token; ovoo holds it in an httpOnly cookie and proxies API calls to Nomad
with it. Upstream: https://github.com/ingvarch/ovoo

## Image

`ghcr.io/ingvarch/ovoo:v0.7.0` (amd64 + arm64)

## Hostname / exposure

- `ovoo.munchbox.cc`, LAN-only (`dashboard-allowlan@file`)
- No oauth2-proxy in front; the Nomad ACL token is the sign-in
- Bridge networking, app port 3000

## Placement

- Constraint: `meta.cloud != oracle`

## Dependencies

- Nomad API at `https://nomad.service.consul:4646`, verified against the
  host's `/etc/nomad.d/tls/ca-chain.crt` via `NODE_EXTRA_CA_CERTS`. The file
  must carry the root as well as the intermediate: Bun rejects an
  intermediate-only trust anchor with `UNABLE_TO_GET_ISSUER_CERT`.
- Vault `secret/ovoo` (`ticket_secret`), generated by the terragrunt
  `passwords` leaf and rendered into `secrets/ovoo.env`. ovoo signs the
  short-lived remote-exec WebSocket tickets with it and refuses to start
  without it.

## Notable configuration

- Health check `/api/config`, the one unauthenticated JSON endpoint
- Traefik sets `X-Forwarded-Proto`, which ovoo reads to mark its cookies
  `Secure`; periodic-job pages need encoded slashes (`%2F`) passed through,
  which Traefik v3.6.7+ does by default
